Windows ​

The administrator policy file (%ProgramData%\ripeat\policy.yaml) is read and enforced the same way, but ripeat does not check its ACL, and nothing tests it on Windows.

Everything compiles and the logic is unit-tested. A CI job also runs scripts/windows-test.ps1 on a GitHub Windows runner (the test notes): real choco, scoop and winget installs, the GitHub download with a lockfile, the PowerShell user and group commands, and restart detection and resume.

Checked by hand on a real Windows 11 ARM64 machine (a VMware virtual machine; steps in the Windows test notes), 2 November 2026:

WhatResult
scoop install ripeat from the bucket, plan, assess, findworked
install and rollback of ripgrep (GitHub release, no administrator rights)worked
install and rollback of node through winget, from an administrator windowworked; the plan marked it admin, MEDIUM risk
policy --apply and rollback (group, disabled user, membership)worked; rollback removed all three

Treat a Windows feature as verified only while that job passes on the current code. The job reports a method as skipped when its tool is missing on the runner, and it runs on a clean server image, not on a real person's machine, so user-account quirks, antivirus and corporate policy are not covered.

product (the "Add or remove programs" check for installers) is unit-tested (the name matching, the "is it there" logic, validation) and builds for Windows, but the registry read and reading the product name from an .msi have not been run on a real Windows machine yet.

installer for .pkg is unit-tested (payload parsing, the allowed-folder and denied-path rules, which paths are owned, signature and receipt parsing, refusing a damaged record), but not run against a real package: no CI job builds one with pkgbuild yet (Vendor installers). Never try it on your own Mac.

installer for .exe is unit-tested (registry diff, Windows command-line parsing, uninstall command choice, argument rules, the same-signer rule, refusals) with stand-in installers and a fake registry list; the real registry and a real vendor .exe have not been run (Vendor installers).

installer for .msi (Vendor installers) was run by hand on a real Windows 11 ARM64 machine with Node.js's official signed MSI (checksum checked, signer read as OpenJS Foundation, msiexec install, msiexec /x undo, saved file deleted). No CI job installs an MSI.

Not yet verified: the lookups added for snap, flatpak, scoop and the Microsoft Store source of winget (Install by name). They are unit-tested against sample output of each tool, and the Ubuntu VM job (snap, flatpak) and the Windows job (scoop; the Store is reported, not required) now exercise them for real. Treat each as verified only while those jobs pass, and the Store lookup only after it has been seen to work on a real Windows machine.

Install by name on Windows: the choco lookup, draft, install and rollback ran for real on the Windows CI runner. The winget lookup is exercised by the same job and counts as verified only while that job passes; its table parsing is the part to watch.
