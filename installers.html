Vendor installers: the installer method ​

For apps a vendor offers as a disk image (.dmg, macOS) or an installer package (.msi, Windows) and that no package manager carries. Other kinds (.exe, .pkg) are not supported: they have no reliable way to be undone.

yaml
platforms:
  darwin:
    method: installer
    package: ollama
    url: https://example.com/Ollama.dmg
    sha256: 5ac60dd9787eef6539403d72740e9d153094fc9e998192025048bee812b86094
    app: Ollama.app          # the app inside the image
    signer: 'Developer ID Application: Ollama Inc. (ABCDE12345)'
    scope: user              # the app goes into ~/Applications, no admin rights
  windows:
    method: installer
    package: ollama
    url: https://example.com/Ollama.msi
    sha256: 0a1b...          # 64 hex characters
    signer: Ollama Inc.
KeyMeaning
urlThe download address. Plain http draws a warning
sha256Required: the checksum the vendor publishes. The download must match it, or nothing is installed
kinddmg or msi; read from the end of the address when left out
appdmg only, required: the app to copy out of the image (a plain name ending in .app)
signerText the vendor's signing name must contain. If it does not, the install is refused
unsignedtrue accepts a file with no valid vendor signature. Rated HIGH; leave it out
scopeuser puts a dmg's app in ~/Applications (no admin rights); otherwise /Applications

Two checks before anything runs ​

  1. The SHA-256 must match the recipe's. A mismatch stops the install.
  2. The vendor's signature must be valid. A checksum copied from the vendor's own page only proves the file arrived intact; a signature proves who made it. On macOS ripeat asks codesign and spctl (Gatekeeper must accept the app, which means a Developer ID signature and, for current apps, notarization). On Windows it asks Get-AuthenticodeSignature for a Valid signature. The signer is shown during the install, and signer: pins who it must be. A file without a valid signature is refused unless the recipe says unsigned: true.

What it does ​

  • dmg: mounts the image read-only, copies that one .app into the Applications folder, and unmounts. Nothing inside the image is run. If an app of that name is already there, ripeat stops: it never replaces an app it did not install. Undo deletes exactly that app and nothing else.
  • msi: runs msiexec /i quietly (/qn /norestart) with administrator rights. The file is kept in $RIPEAT_HOME/installers/<package>/, and undo runs msiexec /x on it, then deletes it. If the installer asks for a restart (exit code 3010 or 1641), ripeat reports it as done and says a restart is needed.

Risk ​

A dmg is MEDIUM: it copies an app and runs nothing. An msi is HIGH: it runs the vendor's installer code with administrator rights, so the plan needs your --accept-risk or a yes at the terminal, and that one answer also counts as the install confirmation (Risk and assess). unsigned: true makes either HIGH. The administrator policy can deny the method (deny_methods: [installer]) or limit download hosts with allow_domains (Administrator policy).

Creating one: ripeat add <name> --url ... --sha256 ... ​

bash
ripeat add ollama --url https://example.com/Ollama.dmg --sha256 5ac60dd9...

You supply the checksum from the vendor's page. ripeat never takes one from the file it downloads, because a checksum worked out from the file vouches for nothing. It then: asks before downloading; downloads and checks the file against your checksum; reads who signed it and (for a dmg) which app is inside; refuses an unsigned file unless you add --unsigned; pins the signer in the draft; and shows the recipe for your approval. Flags: --kind (when the address does not end in .dmg or .msi), --app (when the image holds several apps), --signer (to pin a different part of the signer's name), --unsigned. A dmg draft is scope: user.

Limits ​

  • Fixed address, fixed version. A vendor that replaces the file at the same address breaks the checksum: ripeat refuses the new file until you update the recipe (ripeat recipes check only checks that the address answers, not the checksum).
  • No detection of an msi already installed. The draft for an msi has no check, so ripeat cannot tell the app is already on the machine.
  • Verified so far: the msi flow on a real Windows 11 ARM64 machine with Node.js's official, OpenJS Foundation-signed installer: ripeat add checked the checksum and read the signer, install ran msiexec, node --version worked, and rollback ran msiexec /x and deleted the saved file. The dmg flow (mount, signature refusal, copy, undo, unmount) against a real disk image in a temporary folder on macOS, and the parsing of macOS and Windows signature output. A dmg from a real, signed and notarized vendor download is not yet verified (What has been verified).
